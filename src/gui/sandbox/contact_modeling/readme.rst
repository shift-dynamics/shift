Contact Detection
=================

This folder contains two versions of the gjk algorithm in the gjk.c file.
I believe both files contain the same basic functions and only main and
test functions are different.

They can be compiled using gcc gjk.c.

I have demonstrated the ability to subdivide a unit sphere into six major quads and 6n^2 minor quads where n is any positive number. This yields 6n^2+2 vertices. Furthermore I have demonstrated the ability to associate a five character hash-table code with each unit normal vector for any 0<n<100. For n=99 this would be 58808 vertices, which should be large enough for most applications. The hash-table code covers the unit sphere uniformly, which means that any unit direction vector will decode to the closest normal vector and corresponding closest vertex. A feature of a new procedure is that every unit direction vector decodes to a valid hash-code, which means there will be no hash-code misses for 100% performance efficiency.

I have also described, but not yet tested, the ability to map any closed convex hull represented by any number of vertices onto a quadded unit sphere for any n. Assume that the vertex density of the triangulated convex hull is much higher than that of the quadded unit sphere and that every vertex on the triangulated convex hull has a corresponding unit normal vector. The mapping process computes a mean vertex location on the convex hull corresponding to each unit normal vector on the unit sphere and stores the new mean vertices in a quadded representation of the convex hull. When completed, the new quadded file for the convex hull will have the same topology and unit normal vectors as the quadded unit sphere. Thus the same hash table developed for the quadded unit sphere will apply to any convex hull mapped onto that unit sphere.

Back in February I obtained a different C++-based hash function called phf.cc (perfect hash function). The author provided a c-based interface to phf.cc that simply reads in a list of keywords and generates a perfect hash-table in a fraction of a second. This method means that hash-tables can be generated on the fly anytime needed and only keyword files need be stored. The folder phf in contact_modeling contains the code and a sample key file. It can be modified to read in generated key files. In the next days I will write up a summary of how to generate key files and indirection tables for the unit sphere with arbitrary 0<n<100 levels of 6n^2+2 vertices and 6(n+1)^2 keywords.

The folder “sphere” contains a number of experimental c programs to generate quadrangulated unit spheres with six major quads, 6n^2 minor quads, and 6n^2+2 vertices, where n is even or odd. The files sphe.c and sphes.c are for even n and spho.c and sphos.c are for odd n. I don’t recall the difference between files with and without the s. The even and odd n codes need to be merged into a single program and cleaned up to handle any integer n>0 and generate a unique sphere_#.ply file name where # is replaced by the value of n>0 input to the program. The program also needs to allocate memory corresponding to the magnitude of n supplied.

The quadded spheres generated here would be similar to those generated by applying the Catmull-Clark subdivision algorithm to a unit sphere where n=2^m and m>=0 is an integer. The primary difference is the Catmull-Clark subdivision vertices don’t lie exactly on the unit sphere surface while the sphe.c and spho.c vertices do. Thus the sphe.c and spho.c vertices also represent the corresponding unit normal vectors while the Catmull-Clark subdivision vertices do not. In addition the sphe.c and spho.c vertices and quads are well ordered while the Catmull-Clark subdivision vertices and quads are not.
